# Cubby Native Archive on Apple platforms

The native app follows Apple navigation, controls, typography scaling, and system light/dark appearance. The shared brand roles come from `packages/design-tokens/tokens.json`; `pnpm generate` writes the adaptive color assets and Swift geometry. Keep the existing system AppKit and SwiftUI behavior when applying those roles.

## Appearance

Native system grouped backgrounds, content surfaces, separators, and semantic text colors make records readable and follow system appearance and accessibility settings. Shared neutral brand colors cover custom data surfaces; their generated dark variants preserve contrast in dark mode. Ink is the interaction color, and citron is a sparse focus or attention mark. The seven domains carry their hue on sidebar glyphs and small rounded square section-header chips, matching the web. Web also tints the current row; Mac retains the system sidebar selection highlight. A manifest option tinted with a domain token renders as a neutral chip. Positive, warning, destructive, info and neutral-status tones remain condition colors paired with a word or symbol. A declared option's chip follows its manifest role: a status option is a tinted `StatusChip` led by its SF Symbol, a category option a quiet tint from its declared token, foreground label ink, and its compiled SF Symbol. New glyph pairs must use SF Symbols available on the supported Apple platforms; verify the symbol name against the system catalog.

Use San Francisco through the standard system font design for record identity and dashboard headings. Hierarchy comes from size, weight, and alignment. Use standard SwiftUI text styles for body, controls, lists, forms, and settings so Dynamic Type works. Identifiers use mono; measurements and money use monospaced digits. Real entity images may lead a detail view. If an entity has no image, title and declared data lead it without an empty media box.

Use native `List`, `Form`, `Section`, `LabeledContent`, toolbars, sheets, menus, and split views. The neutral canvas belongs to content; system bars and Liquid Glass retain native presentation. Resting panels use tonal separation and a hairline; overlays may use native elevation. Controls keep native hit behavior, and phone targets stay at least 44 points. Structured amounts use separate native Form rows for Amount, Upper amount and Unit, with distinct labels and native bordered field targets; do not compress multiple editable inputs and Remove into one row. Task-board Move actions name their task for accessibility.

Action color is the second channel: it marks the outcome of a pending decision, separate from condition ("what state?"). Adaptive ActionCreate/ActionCreateSurface are blue, link/attach reuses Slate/Inset, ActionChange/ActionChangeSurface are muted ochre, and remove reuses Destructive. Primary controls stay ink; action color belongs on chips, glyphs and step marks.

## Photo group decisions

Native photo review renders the server's `DecisionStep[]` and `blockedReason`; it does not infer approval readiness. `DecisionSteps` marks each status with a distinct Dynamic Type–scaled symbol: a positive filled checkmark for done, a dashed circle for blocked, a minus circle for not needed and a dark mark on citron for needs input. Summaries wrap rather than truncate. One step expands at a time; answered rows show the summary and Change. The `apply` key is omitted because Create/Attach lives in the footer and atomically confirms and applies the reviewed revisions. Ready batch selections exclude blocked groups.

Photo and label text lead on narrow layouts and sit beside the steps when space permits. Existing Product evidence loads with selection, independently of candidate ranking. Deterministic agreement alone draws a checkmark; missing or model evidence draws a question or warning mark. Ownership and inventory answers save natively through `saveGroups`, preserving the proposal's photo roster, Product edits and explicit ownership. Agent concerns are read-only and use the explicit Resolved operation with an optional reply.

Identity shows every pending Product edit with its current and proposed values and a Remove control that saves through `saveGroups`. The approval effect sentence also enumerates the edits, including when Identity is collapsed. Rejecting the selected Product switches to a create draft named from the observed label, clears Product edits, and drops any inventory link to the rejected Product. Candidate reads track group keys and proposal revisions; changes during a read coalesce into one replacement refresh, and superseded results are not published.

## Hosted workspaces

Connections uses one shared React workspace for the map, four-link exploration,

A record's Connections entry opens it scoped by `source` and `id`: a full-screen

remain native; the title, Done action, authenticated session, and dismissal are
owned by Swift. Secondary Mac windows gate hosted content on the signed-in phase.
Only `/connections` retains this mode; navigation search and record selection
may change within that document, while record links hand off to native.
Connections and Run evidence share one host, session bootstrap, lifecycle and
strict origin/frame checks. A different route or duplicated mode does not gain
bridge authority.

Every entity retains its native detail renderer. A Run’s native console and detail offer one hosted destination for transcript, logs, and AI usage. Native overview, actions, photo review, editors, routing, and coverage remain in place. The evidence sheet has native Done and hands record links back to the native navigator; it does not own record history.

The pilot opens `/RUN-4K7M?nativeWorkspace=run-evidence#evidence` and accepts its canonical `/runs/RUN-4K7M` redirect on the selected server, retaining the pilot query and Evidence hash. A bearer-only POST to `/api/native-workspace/session` creates the configured HttpOnly browser cookie in a fresh nonpersistent WebKit store. It sends no ambient cookies. Logout, host changes, dismissal, and credential revision changes destroy the presentation’s browser state. Exact-origin main-frame version-1 messages support ready, native navigate, changed, authRequired, and updateRequired. Native mutations dispatch `cubby-workspace-refresh`. Authentication redirects and 401 return to native sign-in; 426 shows the update message in the sheet and pins the app's update banner. Retry reboots the session after network failures or web-process termination. External HTTP(S), mail, and telephone links use the system opener; new-window evidence links reuse the pilot, and other records open natively. JavaScript alerts close, confirmations refuse, and prompts cancel; native owns confirmation UI.

The hosted sheet disables global web search and blocks SPA navigation outside its evidence document. Its header omits list breadcrumbs, and same-record hash navigation retains the pilot parameter. Ordinary routes strip it with a document replace before rendering so client search retention cannot restore it or promote a later Run link into hosted mode. Auth redirects retain that parameter and render only the auth-required bridge, while Swift also intercepts auth URLs before loading them. Bootstrap uses the resolved auth session-cookie descriptor. Hosted documents, Start commands and HTTP API calls share the `UPGRADE_REQUIRED` body with `reason: CLIENT_UPDATE_REQUIRED`. Related records hand off to native navigation. Retry replaces both the session host and the displayed WebKit view, so recovery cannot load an unattached browser.

## Density and feedback

Record rows allocate title and trailing-rail width from the current layout proposal. Never feed a row's measured width into state that changes that same row's width: on a physical iPhone this can continuously invalidate Today layout, blocking interaction while loading indicators keep animating. Keep the rail bounded, titles wrapping, and accessibility-size rows stacked without a geometry/state feedback cycle.

A navigable row is exactly one plain-style NavigationLink, so one tap pushes one screen. Records the row mentions (a task's project) go in its context menu, never in a second link inside it. A row's commands (a briefing task's Done) and declared quick actions sit outside that link, beside it or in the swipe and context menu. Declared quick actions are the only filled buttons under a record's hero.

The shell follows Native Archive, details follow Record Dossier, and cooking, imports, reconciliation, photo review, and project tasks retain focused Working Context through their existing controls. Shared presentation reaches specialist screens without replacing their task-specific interaction. Mac list rows prioritize comparison and native selection; iPhone rows use a readable primary line and concise supporting facts. A photo, summary, or inspector never pushes the next action off the useful first screen without purpose. At accessibility text sizes, columns and metrics wrap or stack. Preserve keyboard and VoiceOver labels, Reduce Motion, and Reduce Transparency.

Spacing follows the compact 4/8/12/12/16/16 rhythm (`FieldGuideTokens.Space` xs…xxl, generated from the shared tokens): `lg` equals `md` and `xxl` equals `xl`. Screen and sheet content uses explicit token padding (`Space.md`/`Space.lg`, 12 points), never SwiftUI's default `.padding()`. Tab roots and pushed screens use inline navigation titles. Generic record navigation names the entity kind; the summary carries the full human record title once in a compact headline. Toolbar crowding must never be allowed to erase record identity. Other screens avoid repeating their navigation title in content. Record counts beside a sidebar or catalog row are plain, muted, tabular digits at the trailing edge, with no badge box. Density never shrinks a phone target below 44 points.

Generic record detail follows Apple's own record views. The header is the record image (56 points on Mac), the title, and one muted line naming the kind, the mono identifier and one key fact; it does not repeat a fact as a large hero value or show fetch age. The declared `detail.summary` roster renders directly below the header as up to eight applicable summary cells, adapting to available width and Dynamic Type. Linked fields, bounded related-record previews, concise report figures/progress and charts share this one roster. Expense charts use Swift Charts for twelve months of actual Expense spend, with signed bars around zero (refunds in secondary gray) and a titled total. Empty optional relationships may disappear; unknown values, loading and failed reads stay explicit, with Retry. Workflow forms and commands remain in their owning sections. Prose spans the full width. On Mac, facts form a Get Info grid: disclosure section headers, a right-aligned secondary label column beside leading values, and roughly 20-point read-only rows; reference values are accent links without chevrons. On iPhone and compact iPad, facts use inset grouped sections with `LabeledContent`; read-only rows are about 34 points with compact section spacing, while links and buttons keep 44-point targets. Declared `activityRelations` render an Activity section grouped by day (related records by date plus record changes, using shared `RecordListRow` rows); calendar-day dates never shift by zone. Wide Mac detail places Activity in a right column. Sections, relations and connections with no data are hidden, and their create actions move to the toolbar ••• menu, which also opens Connections. Connected records and the raw record are collapsed disclosures at the end of the detail. Editing and specialist workflow forms remain Form. Liquid Glass belongs to controls and navigation, while record content stays flat. Generic detail Lists, Image details and Run lists use the shared `fieldGuideDetailDensity` helper for compact edges, native surfaces and compact section gaps. Record and source references use value-based NavigationLinks with plain button styling; apply `navigationLinkIndicatorVisibility(.hidden)` to the compact List child so List does not add a second disclosure indicator. Retain the enclosing NavigationStack's existing Route registration: adding destinations inside lazy List rows is invalid, and mutating the root Navigator bypasses sheet-owned stacks and their drafts. Text may grow freely at accessibility sizes.

Fields show no visible explanation button. On Mac the label carries a `.help` tooltip and the row's context menu offers Explain; on iPhone the long-press menu offers Explain; both keep an accessibility action. The shared explanation presenter composes Explain with override actions in one row menu: nested label menus must not be masked by a parent override menu. An inherited value is one row: the value with a muted "Inherited from <record>" line. Set here and Use inherited live in that row's context menu.

An absent live explanation value uses neutral wording: the nullable response does not distinguish a computed null from an unavailable live result.

Editor rows use one label style: `LabeledContent` (label leading, value or field trailing) for every single-line field, picker, token list and reference, never a caption above the input; multi-line prose keeps its label above. A staged action is an ordinary draft edit; the editor adds no separate save notice. A token list is one disclosure row whose value lists the tokens. The record emoji draws one large glyph and keeps only the last character entered.

All Swift record lists share `RecordListRow`: a two-line row of about 44 points with a 32-point thumbnail on Mac (30 on iPhone), the title and a trailing value on the first line, and up to three facts joined by " · " plus a relative date on the second. Identity and rail keep equal layout priority so the expanding title frame cannot starve the rail of width and turn status/date text into an oversized vertical column. `EntityRowView` supplies manifest-driven facts for Browse, Today meals and nested detail lists; ordinary relations and journal record headers use that same adapter. DatePicker inputs, calendar axes/period headers and diagnostics retain their purpose-specific values, including exact seconds and captured offsets. Detail headers lead with the declared `detail.hero.when` date when present. For generic entities, choose the declared hero chip or highest-priority mobile trailing fact, then quality as the fallback; selected semantic dates occupy the second rail line. Use declared mobile subtitle priority for context and retain every remaining selected fact in a wrapping supplement. Do not fabricate state or dates for projections without them. Rail values use plain text and restrained semantic color, with independent field explanations and source attribution. The rail responds to the available width; accessibility text sizes stack its content. Titles, sources, chips and facts grow naturally rather than clipping or horizontally scrolling. Textual explanations retain their existing accessibility labels when the visible control is icon-only. Keep minimum 44-point row and explanation targets, small explicit row padding and complete multiline measurement so text never touches or crosses separators. Every row reserves its thumbnail slot: use the server-selected direct/related display image, then the declared record emoji, dynamic entity icon, entity glyph, and finally a neutral placeholder. Loading and failed images retain that slot and its fallback. Determinate progress (photo preparation) and named write or check progress ("Checking booking…") keep their own `ProgressView`. In-flight writes keep their existing dismissal rules.

Search results push within the originating Search stack on every platform, preserving its query
and Back history. Editing the query or scope immediately clears the previous results while the

its original control remains the retry path. Session and server changes discard retained retries.

## Field applicability

Native table and detail fields refused by an existing same-record classification policy show a
quiet dash with the manifest's reason available to accessibility and hover help. They expose no
edit, suggestion or resolution action. The manifest projects these rules from classification
policies, including nested classifier read paths; native does not own account-kind exceptions.
Server-resolved allocations remain visible with their evidence when manual assignment is refused; assignment controls remain unavailable.
Applicable empty fields remain editable, and inherited values retain their override actions.
A reclassification omits newly refused draft fields from outgoing writes; the server owns
clearing incompatible stored values. Reload seeding uses the incoming classifier throughout.

## Continuous record detail

Full record routes show every declared section in one continuous native list, including sections formerly selected as another record view. Section bodies remain open; pagination and explicit show-more controls still bound collections. Empty relations and connections are hidden; their creation actions stay reachable from the toolbar ••• menu. Raw record details remain available in a collapsed disclosure.

The Contents toolbar control opens grouped headings with indented, expanded subsections. Native declarations do not carry web workspace groups, so generic records keep declared sections under Record in their existing reading order, followed by Relations and Provenance. iPhone presents a native sheet, iPad a native popover, and a Mac detail at least 700 points wide toggles an adjacent outline (smaller windows use a popover). Selecting a subsection closes Contents and scrolls the existing detail; scrolling marks the current subsection. Each target identity, focus binding, and geometry measurement belongs to one subsection header, while the enclosing section resolves body emptiness. Never attach those target modifiers to a multi-row Section. Use standard native controls without entrance animation. Run console and Image detail follow this rule; Run evidence and Connections remain isolated hosted routes.

Image diagnostics remain visible in continuous detail, but Vision comparison and stored-analysis reconciliation begin only from the explicit Run diagnostics action. Leaving or cancelling releases the loading state so the action can be requested again. A Contents jump is consumed after its header receives focus; reconstructing a lazy header never replays a completed jump.

## Compound calendar ranges

Generic date-range fields edit Start and End with independent toggles and calendar-only
pickers. Removing the last endpoint clears the whole field. Saves replace the complete
range and reject reversed endpoints. Periods with one endpoint display “From” or “Through”;
a deadline with only a start displays that date. Calendar days never become UTC instants.

Derived envelope states share an immediate info-colored Updating dot on lists
and detail fields, pulsing only when Reduce Motion is off. Inherited values
retain their linked provenance caption; auto suggestions say Auto suggestion.
The full derived decision chain remains a native follow-up to ADR 0021.
