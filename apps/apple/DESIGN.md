# Cubby Native Archive on Apple platforms

The native app follows Apple navigation, controls, typography scaling, and system light/dark appearance. The shared brand roles come from `packages/design-tokens/tokens.json`; `pnpm generate` writes the adaptive color assets and Swift geometry. Keep the existing system AppKit and SwiftUI behavior when applying those roles.

## Appearance

Native system grouped backgrounds, content surfaces, separators, and semantic text colors make records readable and follow system appearance and accessibility settings. Shared neutral brand colors cover custom data surfaces; their generated dark variants preserve contrast in dark mode. Ink is the interaction color, and citron is a sparse focus or attention mark. The seven domains carry their hue on sidebar glyphs and small rounded square section-header chips, matching the web. Web also tints the current row; Mac retains the system sidebar selection highlight. A manifest option tinted with a domain token renders as a neutral chip. Positive, warning, destructive, info and neutral-status tones remain condition colors paired with a word or symbol. A declared option's chip follows its manifest role: a status option is a tinted `StatusChip` led by its SF Symbol, a category option a quiet tint from its declared token, foreground label ink, and its compiled SF Symbol. New glyph pairs must use SF Symbols available on the supported Apple platforms; verify the symbol name against the system catalog.

Use San Francisco through the standard system font design for record identity and dashboard headings. Hierarchy comes from size, weight, and alignment. Use standard SwiftUI text styles for body, controls, lists, forms, and settings so Dynamic Type works. Identifiers use mono; measurements and money use monospaced digits. Real entity images may lead a detail view. If an entity has no image, title and declared data lead it without an empty media box.

Use native `List`, `Form`, `Section`, `LabeledContent`, toolbars, sheets, menus, and split views. The neutral canvas belongs to content; system bars and Liquid Glass retain native presentation. Resting panels use tonal separation and a hairline; overlays may use native elevation. Controls keep native hit behavior, and phone targets stay at least 44 points. Structured amounts use separate native Form rows for Amount and Unit, revealing Upper amount through Add upper amount unless a saved upper value exists, with distinct labels and native bordered field targets; do not compress multiple editable inputs and Remove into one row. Task-board Move actions name their task for accessibility.

Action color is the second channel: it marks the outcome of a pending decision, separate from condition ("what state?"). Adaptive ActionCreate/ActionCreateSurface are blue, link/attach reuses Slate/Inset, ActionChange/ActionChangeSurface are muted ochre, and remove reuses Destructive. Primary controls stay ink; action color belongs on chips, glyphs and step marks.

## Photo capture and handoff

Capture has one primary Scan action. Its secondary photo sources and All photos
open the same batch review immediately after selection, without an assign/import
dialog. Photo rows retain the same layout for one photo or many: a 112-point,
tappable preview, capture date, independent selection control, and a directly
tappable destination below. Compact row insets replace the separate hero,
filmstrip and repeated selection status. Batch destination changes act on exactly
the selected photos; a row destination change scopes itself to that photo.

Confident record matches propose safe destinations before the final Add action;
analysis never blocks manual choices or overwrites them. Type-only and uncertain
matches stay unassigned with direct choose-existing/create-new affordances.
Undated photos require a member-supplied date where the destination requires one;
staging preserves that date instead of inventing a capture timestamp.
Mixed-date related matches resolve separately per capture day; explicitly chosen
destinations may still combine photos. Add explains remaining destination or
duplicate decisions beside its control. After commit, show destination summaries
and links to confirmed records. Refused writes retain the same draft and staged
uploads; unknown outcomes offer Check status instead of another write.

Import selected belongings is secondary inside review and carries the selected
photos into the existing durable import setup. Ownership, location, processor and
notification choices stay there. The new-import action remains in a fixed bottom
bar while defaults and existing runs scroll. The sweep location stays visible and editable. Persist
only its id in device preferences; restore it after a successful location load,
and silently clear it if the location was deleted. Camera and Photos permission
denials explain the blocked action and offer Open Settings (System Settings on Mac).

Camera preparation retains the captured bytes until it succeeds so Retry prepares the same photo. Scanner startup failures show the raw diagnostic with Retry and the existing manual code entry. Photo destination changes register their undo with the sheet's system UndoManager; the toolbar has no custom Command–Z binding, preserving text editing undo.

New belongings imports default to owned items and the signed-in member. A storage
location is optional during capture and required before adding stock during review.
Keep processor choice under Import options. Carry these defaults in the durable
Run; Send to computer shares the same Run at its Photos anchor while upload and
analysis can continue. Clean identity steps stay folded; missing destinations and
real concerns use the server-projected attention state.

## Photo runs hand off review

Native owns a photo Run's capture, upload, description progress, per-photo recovery, Start grouping, Live Activity and attention state. Deciding proposed groups is web's: comparing candidates, editing proposed Products and ownership, and approving or discarding groups happen at `run/<id>#photo-batch`. The Run console draws that slot as one handoff row, Review photo groups on web, ahead of the reports; the console shows how many groups are ready but no per-group controls.

## Work hands off the job queue

Native Work owns this device's work: the device backlog, the companion worker, local activities and the automatic-work toggle, then Runs in progress and Runs needing attention. Household decisions, improvements, lanes, waiting reasons, Job retries, explanations and leases live in web Work at `/activity`. The automatic-work toggle leads This device as a normal row. Native Work ends with All changes and one handoff row, Open Work on web; image-work concurrency lives in Settings › Advanced. Existing internal Activity route identities remain unchanged.

A workspace opened from More is presented by the persistent record screen; dismissing the menu must not dismiss the workspace.

remain native; the title, Done action, authenticated session, and dismissal are

may change within that document, while record links hand off to native.

bridge authority.

## Field applicability

Native table and detail fields refused by an existing same-record classification policy show a
quiet dash with the manifest's reason available to accessibility and hover help. They expose no
edit, suggestion or resolution action. The manifest projects these rules from classification
policies, including nested classifier read paths; native does not own account-kind exceptions.
Server-resolved allocations remain visible with their evidence when manual assignment is refused; assignment controls remain unavailable.
Applicable empty fields remain editable, and inherited values retain their override actions.
A reclassification omits newly refused draft fields from outgoing writes; the server owns
clearing incompatible stored values. Reload seeding uses the incoming classifier throughout.

## Continuous record detail

Full record routes read glance → sections → relations in one continuous native list.

- **Glance.** The hero carries the title and one caption: the projected breadcrumb (`Home › Shelf B`) and the declared `hero.when`, falling back to the list subtitle. The record code is not in the caption; it stays in More → Copy shortcode. On iPhone a 92-point image tile sits beside a `title3` title by default, so the glance and action bar stay on the first screen; tapping the tile opens the full-screen gallery (the cover, then the record's other uploaded photos). A record may declare `detail.heroMedia: "banner"` for a full-width image capped near a third of the viewport; none does today. Without a photo the iPhone title leads unless the record has an image or emoji of its own. iPad and Mac keep the 56-point image beside the title. At accessibility sizes the tile stacks above the title. Beneath the hero, adjacent scalar cells among the first four summary cells sit two across (one column at accessibility sizes). Record links, related records, reports and charts take the full width, and the remaining cells follow.
- **Action bar.** Under the hero, `ActionPlacement.actionBar` draws at most four tiles: declared `detail.quickActions` filled, then routine one-tap verbs, native flows and declared `detail.quickFields` tonal. These are the only filled buttons on a detail. Two tiles read as wide labelled buttons, three or four stack icon over label, and accessibility sizes stack the tiles vertically, after the summary on iPhone so the record’s facts lead. Mac draws content-sized native buttons in one leading row, falling back to a column when needed. Destructive verbs never appear here. An unavailable tile stays in place, dimmed, and says the server's reason when tapped (VoiceOver reads it as the hint). A quick field tile opens that field's in-place editor in a compact sheet, because the field may live in a summary cell rather than a section row; a field native cannot edit in place opens the whole-record editor. Native flows run from the same tiles and More: `receiveExpense` opens the receive sheet and `locationPhotoPass` pushes the photo pass, so no entity carries a hardcoded Fieldwork section or Receive supplement. Record handoffs (a transaction's Review booking on web) draw one inline web row in their declared section plus a More item.
- **Inline edit.** Simple fields (text, number, money, one option, a date, a toggle, one reference) edit in place on a detail unless the field declares `display.inlineEdit: false`. iPhone taps the row; Mac double-clicks the value; both offer Edit in the row menu and VoiceOver an Edit action. A row whose value is itself a link (a reference, an external URL) keeps its tap for the link and edits from the menu. Editing swaps the row for the editor's own `EntityFieldControl` with Cancel and Save, over an update model scoped to the record: it re-reads the record as its baseline, and Save sends a single-field patch (`EntityPatch.diff`) through the ordinary update path, so validation, envelope controls (Use inherited, Keep this value, Set to …) and Why this value match the editor. Server validation renders under the control; the draft survives a refused save. Structured, collection, multi-line and range fields keep the editor sheet or their web handoff, summary cells stay read-only, and toolbar Edit stays for the whole record.
- **Suggestions.** A record's pending field Suggestions (`suggestions.list`) draw a quiet marker under the affected row: the proposed value with Accept and Dismiss, sent through `suggestion.review`. When there are several, or one has no visible row, a "N suggestions" disclosure near the glance lists them with Accept for the clean ones (`suggestion.reviewBatch`). Accept applies on the server and Dismiss records the miss; native holds no suggestion logic (ADR 0025).
- **More.** The toolbar ••• renders `ActionPlacement.more` in groups: declared verbs, with unavailable ones dimmed and the server's reason as the subtitle; native flows, Add photo, Create related and Connections; Copy link, Copy shortcode and Share; Open on web with every reviewed handoff; then Delete and other destructive verbs last. Mac adds Edit Record ⌘E, Delete Record… ⌘⌫ and an Actions menu listing the record's verbs with the same availability. Merge is a list-selection action, never a detail one.
- **Delete.** Delete is quick: More → Delete (or ⌘⌫, or the list's trailing swipe) asks one native confirmation dialog, then deletes and leaves the record. No intermediate sheet appears unless the verb declares inputs; a refused delete shows the server's raw error. There is no undo: confirmation costs one tap for a two-person household, and the server has no restore operation to undo against.
- **Sections.** Declared sections follow in declaration order, including sections formerly selected as another record view. A field a summary cell shows is not repeated in a later section. Section bodies remain open; pagination and explicit show-more controls still bound collections.
- **Relations.** A relation heading carries its total (`Photos · 12`). Connection evidence appears only for an indirect record (its path and hop count); a direct one-hop record shows neither "Direct" nor "1 hop". A related record's declared row command (a subtask's Done) repeats beside its row, outside the row's link. An empty relation collapses to one quiet row with the declared empty copy or `Title · 0`, and its creation action stays reachable from the toolbar ••• menu. Load and evidence failures use the inline failure row with a 44-point retry. **Open all** opens the target list with the relation filter. Empty connections are hidden. Raw record JSON appears only with developer overlays.

Edits carry no version check. Web and native both send only the fields that changed (native `EntityPatch.diff`), so two members editing different fields never collide, and per-field last-write-wins is accepted for a two-person household rather than adding optimistic-concurrency tokens to every write.

The Contents toolbar control opens grouped headings with indented, expanded subsections. Native declarations do not carry web workspace groups, so generic records keep declared sections under Record in their existing reading order, followed by Relations and Provenance. iPhone presents a native sheet, iPad a native popover, and a Mac detail at least 700 points wide toggles an adjacent outline (smaller windows use a popover). Selecting a subsection closes Contents and scrolls the existing detail; scrolling marks the current subsection. Each target identity, focus binding, and geometry measurement belongs to one subsection header, while the enclosing section resolves body emptiness. Never attach those target modifiers to a multi-row Section. Use standard native controls without entrance animation. Run console and Image detail follow this rule; Run evidence and Connections remain isolated hosted routes.

Image diagnostics remain visible in continuous detail, but Vision comparison and stored-analysis reconciliation begin only from the explicit Run diagnostics action. Leaving or cancelling releases the loading state so the action can be requested again. A Contents jump is consumed after its header receives focus; reconstructing a lazy header never replays a completed jump.

## Compound calendar ranges

Generic date-range fields edit Start and End with independent toggles and calendar-only
pickers. Removing the last endpoint clears the whole field. Saves replace the complete
range and reject reversed endpoints. Periods with one endpoint display “From” or “Through”;

and detail fields (queued or waiting work, or a stale cache), pulsing only when

retain their linked provenance caption; automatic own values say Automatic.
