# Porcelain Transit web-PWA surface brief

- **Scope and mode:** Entire `apps/web` PWA; Operate. One big-bang branch with
  bisectable target commits and no partial mixed-world merge.
- **Audience and job:** One trusted household uses Cubby at a desktop desk for
  dense scanning/editing and on a phone around the house for lookup, capture,
  and action. Preserve all existing product truth and workflows.
- **Direction:** Porcelain Transit. Fuse the route-led approved mock's expanded
  domain wayfinding and horizontal relationship path with the table-first mock's
  density, collapsed rail, and vertical inspector spine.
- **Memorable moment:** Selecting a row keeps the grid in place and reveals a
  truthful, clickable route through connected entity types in a docked desktop
  inspector; mobile turns that route into a strip and full detail journey.
- **Constraints:** Light mode only; expressive stable domain colors; 28/32px
  desktop tables but normal-density forms/dashboards; 44px phone targets;
  preserve RTable, routing, mobile shell semantics, accessibility, safe areas,
  saved layouts, keyboard behavior, and specialist workflows.
- **Approved comps:** `.impeccable/mocks/porcelain-transit-route-led.png` and
  `.impeccable/mocks/porcelain-transit-table-first.png`.
- **Completion:** The route ledger, direction contract, functional/visual/a11y
  gates, detector, finish review, 18/20 audit threshold, exact CI, and design
  documentation must all close. See `docs/plans/porcelain-transit-ui-overhaul.md`.
